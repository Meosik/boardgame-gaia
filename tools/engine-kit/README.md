# 게임 엔진 전달본 준비

기존 엔진/학습 실행을 변경하지 않고 현재 작업 트리에서 필요한 파일만 추출합니다.
원격 저장소 생성·Git 초기화·커밋·업로드·학습·서비스 배포는 하지 않습니다.

```sh
# 원본 레포 루트. 반드시 아직 없는 레포 밖 폴더를 지정하세요.
python3 tools/engine-kit/export.py --output /tmp/gaia-engine-kit
python3 -m unittest discover -s tools/engine-kit -p 'test_*.py' -v
```

사용자가 명시적으로 요청한 **비공개 관전 UI/런타임 이미지 포함 모드**는 다음과 같습니다.
기본 모드는 계속 엔진 전용이며 이미지가 포함되지 않습니다.

```sh
python3 tools/engine-kit/export.py --with-viewer --output /tmp/gaia-engine-kit-with-viewer
```

이 모드는 기존 관전 UI와 정규화된 런타임 이미지, 로컬 설치/실행 스크립트를 추가합니다.
미사용 원본 스캔·룰북·기존 게임 기록·학습 모델·게임 서버는 제외합니다. 이미지를 넣으라는 사용자
승인은 배포 허가 증빙이나 라이선스 선택으로 기록하지 않으며, ASSET-NOTICE.md를 포함합니다.
전달본의 VIEWER.md에서 설치 후 예제 AI를 실행하고 브라우저로 관전하는 방법을 안내합니다.

파일 목록은 `export.py`의 명시적 파일/확장자 허용 목록으로 제한됩니다.
기존 출력 폴더는 덮어쓰지 않으며 소스 심볼릭 링크는 거부합니다. `.git`, `.env`,
개인 기록, 웹 서버, 프런트엔드, 룰북/이미지, 학습 모델, 교사 실험, 배포 스크립트는
포함하지 않습니다. 필요한 Rust `src/*.rs`, 규칙 `data/*.toml`은 현재 버전을 그대로
복사합니다. 출력 `MANIFEST.json`으로 파일 해시를 확인할 수 있습니다.

## 선택한 방식과 한계

- **선택:** 별도 소스 전달본 + 최소 Python 설치 + 선택적 AEC 의존성.
- **전체 Git 복제 대신:** 불필요한 파일과 과거 이력의 유출 범위를 줄입니다.
- **공개 wheel/패키지 등록 대신:** 라이선스와 지원 플랫폼 결정 전 로컬 검증이 가능합니다.
- **한계:** 전달본은 원본과 별개 스냅샷입니다. 업데이트마다 새 폴더를 생성하고 검증해야 합니다.
  임의 소스 파일에 포함된 비밀 문자열까지 자동으로 안전하다고 인증하지 않습니다.

## 보내기 전 점검

1. 출력 README에 따라 별도 가상환경에서 설치·테스트·예제 한 판을 실행합니다.
2. 포함 파일/해시와 민감 정보, 코드·규칙 데이터의 이용 및 배포 조건을 검토합니다.
3. 소유자가 라이선스/수신자의 이용 범위를 결정합니다. 이 도구는 라이선스를 선택하지 않습니다.
4. 승인 후 전달본만 새 비공개 Git 저장소 또는 압축 파일로 전달합니다.

현재 `release_ready: false`는 공개 조건이 미확정임을 표시합니다. 설치 테스트 통과만으로
공개 준비 완료로 바꾸지 마세요. 원본 코드의 Git 이력이나 외부 자료를 추가 복사하지 마세요.
